天名 -Amana-

公開中

「名前をつけたくなる空へ」をテーマに、いまの空を描き、外で出会った空に名前を授けるiOSアプリ。

時刻・位置・太陽の高さと実際の雲量から、いまの空を端末の中で描きます。外で空を撮ると、写真そのものはAIに渡さず、色・時刻・天気から取り出した特徴だけをもとに、その空の名前を生成します。電波のない場所でも動き、写真は端末の中だけに保存する、プライバシーを優先した設計です。

名付けた空は図鑑に集まり、気象衛星の画像と並べて「宇宙から見た同じ空」も見られます。空がきれいになりそうな日の通知や、ウィジェット・StandBy向けのサブスクリプションも実装し、2026年8月の公開から約1か月で10回以上アップデートしました。RevenueCat主催のハッカソン「Shipaton 2026」にも参加しています。

技術Swift、SwiftUI、WeatherKit、オンデバイスAI、WidgetKit、アプリ内課金（サブスクリプション）、気象衛星画像

そらもよう

公開中

空の写真を撮って、編集して、集める、空専門の写真SNSアプリ。

投稿した写真をAIが分析して空の種類や色を自動で分類し、「あの夕焼けの色」から空を探せる色検索につなげています。27種類の編集ツールに加え、写真から空の部分だけを見つけて補正する「空を整える」、過去の編集の傾向から空のタイプごとに仕上げを提案する「AIで自動編集」、4枚の写真をつないで広い空にする「広角合成」などを実装しました。

フォローやフィード、連続記録、ホーム画面ウィジェットも備え、2026年4月末からの4か月で20回以上アップデートしています。

技術Swift、SwiftUI、Firebase、Core Image、画像認識AI、WidgetKit、fastlane

Escape Nine: Endless

公開中

9マスの盤面で、ビートに合わせて影から逃げ続ける脱出ローグライク。

全100階層に、霧やマスの消失などの特殊ルールと、スキルの異なる4キャラクターを用意しました。テンポはBPM70から200まで加速し、Game Centerの世界ランキングと日替わりのデイリーチャレンジで、繰り返し挑戦したくなる設計にしています。

新規プレイヤー向けの段階的なチュートリアル、チュートリアルのVoiceOver読み上げ、「視差効果を減らす」設定に合わせた触覚フィードバックの自動オフなど、アクセシビリティにも取り組みました。最初はReact Nativeで作り始めましたが、音とのタイミング精度を優先してSwiftで作り直しています。

技術Swift、SwiftUI、MVVM + Combine、AVFoundation、Game Center、Firebase、AdMob、アプリ内課金

Hero Alias

公開中

名前を入れるだけで、AIがオリジナルの能力・異名・キャラクター画像を生成するエンタメアプリ。

入力された名前から、AIが超能力の設定、ヒーロー名（またはヴィラン名）、マンガ風のキャラクター画像を順に生成します。画像生成には1日の無料枠を設け、月額プラン2種と買い切りチケットで上限を広げられる課金設計にしました。Appleでサインインによるデバイス間の同期や、アプリ内からのアカウント削除にも対応しています。

消防法令MCPサーバー（fire_law_mcp）

検証中

消防法令について、AIが条文にもとづいて答えられるようにする自作のMCPサーバー。

消防の仕事では、設備の設置基準などを法令の条文どおりに確かめる場面が多くあります。AIが「それらしい答え」を作ってしまわないよう、e-Govの法令データを全文検索できる形で持ち、RAGと組み合わせてAIに条文を渡す仕組みをPythonで作りました。試作からレビューと改良を重ねてv5まで育て、消防法施行令の全体と消防用設備等25種に対応し、pytestによる90件のテストを通しています。毎年の法改正に追いつくための更新手順も、Claude Codeで回せる形に整えました。

条文やマニュアルを正確に引く必要がある仕事（行政の手続き、社内規程、業界のルールなど）にも、同じ設計を応用できると考えています。

技術Python、MCP、RAG、SQLite FTS5、e-Gov法令API、pytest

SNS運用の自動化ワークフロー

構築済み

宣伝動画の生成から、確認・承認・配信までをつないだ自動化の仕組み。

ParkPediaとEscape Nineの宣伝のために、動画素材の生成、画像認識AIによる品質チェック、Notionでの承認、TikTok・Instagram・Facebookや広告への配信までを、7本のワークフローに分けて自動化しました。公開前にNotionで人が承認する工程を挟み、AIが作ったものがそのまま外に出ない構成にしています。

技術n8n（VPSでセルフホスト）、Kling（動画生成）、Notion API

開発の進め方

プログラミング未経験から始め、AIに解説させながら覚えてきました。いまはAIに「書かせる」ことより、AIの成果物を確かめられる仕組みを作ることを大事にしています。

  1. 先に要件を文章にする

    要件定義、設計、タスクの順に仕様を書き、プロジェクトのルールをCLAUDE.mdにまとめてから、Claude Codeで実装を始めます。

  2. 計画役と実装役を分ける

    設計やレビューを担当するモデルと、実装を担当するモデルを使い分け、一つのAIに丸投げしない体制で進めます。

  3. テストと自動チェックで確かめる

    ParkPediaではGitHub Actionsでテストやセキュリティ検査を自動化し、消防法令MCPサーバーは90件のテストで動作を確認しています。

  4. 影響の大きい変更は、承認してから反映する

    ファイルの一括整理のような作業は、gitでブランチを切り、差分を確認して承認してから反映する手順にしています。

公開後は小さな改善を細かく出すことを重視していて、そらもようは4か月で20回以上、天名は公開から約1か月で10回以上アップデートしました。作業ログはClaude Codeのフック機能で自動記録してObsidianに蓄積し、振り返りや発信に使っています。

使っているAIツール：Claude Code（メイン）、Claude、ChatGPT、Codex、Cursor

経歴とこれから

消防職として勤務しています。IT業界の外からのスタートですが、だからこそ「技術として面白いか」より「現場で本当に使えるか」を基準に作っています。

現場には、紙や手作業が残る業務、専門知識を調べる手間、引き継ぎや教育の負担など、ソフトウェアとAIで軽くできる課題がたくさんあります。つながる119や消防法令MCPサーバーは、その課題を自分の職場の知識で試しているプロジェクトです。

これからは宮崎を拠点に、中小企業や店舗、教育、福祉、行政といった身近な現場に、AIを実際に使える形で届けたいと考えています。

目指すのは、AIを導入することではなく、AIで現場が少し良くなることです。
